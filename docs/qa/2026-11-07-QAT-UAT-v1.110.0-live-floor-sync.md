## 2. "Cloud sync issue" — found in the live logs, not guessed
Last-hour API / database logs showed three things:
1. **`POST /customers → 403` in bursts of ten, every ~25 minutes**, each burst ending in the "Cloud sync issue / Sync rejected" toast. Cause: a record carried over from another restaurant derives the same cloud id as that restaurant's row, the upsert lands on it, and row-level security refuses the UPDATE ("USING expression"). It can never succeed here — and the code retried forever and said "set aside" while setting nothing aside. **Fixed:** such a record is now really set aside (kept, never uploaded, forgotten by the retry queue), with no toast; Admin → Data Integrity lists them with a "Try again" button. Only this exact refusal is set aside; a network error still retries.
2. **`rpc/orders_waiting_by_branch → 401` once a minute, all day** (a session without a signed-in login asks the database every minute and is refused each time). **Fixed:** it stops asking after the first refusal.
3. `orders` insert **409** (duplicate bill number) twice in the hour: handled by the existing renumber-and-retry (v1.108.0), invisible to the user — left as is.
Also: the waiter-call poll on the floor runs every 45 s and not while the tab is hidden.
**Proof:** 11 tests (what counts as a foreign-record error and what does not; the set-aside list; the store's three call sites pinned). **Not proven here:** the live site's behaviour after deploy — check the logs again an hour after deploying; the 403 bursts should be gone.

## 3. Privacy policy and erase on every device
* **Privacy policy page** `#/privacy` (public, no sign-in): what is kept, why, who sees it, how long, the customer's choices, protection, how to ask — names the restaurant and its phone. A starting text, not legal advice. Linked from Settings → General → Privacy.
* **Erase now reaches every device.** An erase leaves a marker in the shared settings: a one-way hash of the phone key (never the number) and the time. Each other device applies it when it next opens or its settings change — but only to what existed up to that time (a customer who ordered again afterwards is a new customer). 7 tests.

## 4. One title on every page
57 pages use one title block (icon tile, title, one-line subtitle). Before / after screenshots were checked on eight screens.

## 5. Not done — said plainly
* **Whole-app translation** (Urdu / Arabic for every page): not built in this release. Only the dictionary keys and the menu are translated.
* **The 38 screens' master-detail layouts** from the design package (list on the left, details panel on the right) are not rebuilt; titles, gutters and overflow are unified.
* Real phone / tablet / second till / iOS / paper printing, and a real order from a website, were not exercised here. Release APKs still need the four `ANDROID_*` secrets.
