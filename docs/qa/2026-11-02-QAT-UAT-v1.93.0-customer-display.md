# QAT and UAT — DT POS Enterprise v1.93.0 (Customer Display, Kitchen Display Center, second screens)

Master directive #12, the **Customer Display**, brought over from the offline POS (v1.21.0), plus the Windows shell's second-screen support. This is not a new design: the screens, the settings and their tests come from the offline POS, adapted where this app's architecture differs (Supabase instead of one local database, branch scoping, the egress rules).

## 1. What was built
### Customer Display (`#/customer-display`)
- A page for a second monitor facing the customer. It shows the shop's name and logo, **Now Serving** (orders being prepared, orders ready to collect), a message along the bottom, banners or video chosen by the shop, and — beside them — **the bill as the cashier rings it up** (items, quantities, amounts, discount, service charge, tax, total, and what was paid / the change).
- **Ten designs** (Premium, Modern, Minimal, Colourful, Restaurant, Promotional, Large Order, Order + Advert, Media Focused, Compact), each with automatic mode by screen shape, a banner/orders split (70/30, 50/50, 30/70, orders only, or an exact percentage), image and video banners (stored on this computer), a heading, the ready-order hold time, and the credit line ("Powered by Digital Target", which the shop can turn off).
- **Announcements:** the order number is spoken when an order becomes ready — English and Urdu wordings, a second language after the first, repeat count, a chime first, and the chime can be sent to a chosen audio output. A voice that is missing is reported plainly and the line is skipped; it never stops an order or the display.
- **What the customer is never given:** the till publishes an allow-list (item names, quantities, amounts, labels, totals, paid and change). Cashier, waiter, rider, customer name/phone/address, table, notes, payment account and kitchen details are not in it, and the page re-applies the allow-list when it reads the bill back.

### Kitchen Display Center (Kitchen Display → TV Mode)
- TV Mode now opens the **Center**: which screen the kitchen watches, the kitchen board's own settings (seven designs + automatic, columns across the board, a beep for a new ticket, the new order number spoken aloud, the credit line), and the Customer Display settings above. In the Windows app the monitors are listed and the display opens full-screen on the chosen one; in a browser it opens in a new tab.
- **The kitchen TV board (`#/kds-tv`) is the template-driven board from the offline POS:** a lane per stage (New, Preparing, Ready, Delivery, Completed), a short "recently finished" memory (cancellations are noticed within seconds), a NEW flag that expires, reduced-motion respected, the colours fixed so a cook reads the board by colour alone. It follows the settings above and a settings change reaches an open board without a restart. **This replaces the older single-grid board**, which ignored those settings.

### Windows shell (separate repository, `dtpos-desktop`, commit `e381d61`, local, not pushed)
- Second-screen IPC: list displays, open the kitchen/customer display full-screen on a chosen monitor, close it, ask whether it is open, pick a media file. Display names come from the operating system with a resolution fallback — never a guessed cable type. The shell listens for no monitor-plugged-in event, so connecting a monitor never opens or moves a window; a window opens only when the owner presses Open. 50 shell tests pass (2 new).

## 2. Found while doing this, and fixed
- **The display window would have run the till's workers.** Routed inside the till shell, `#/customer-display` would also have shown the sidebar and header and run a second set of the shell's workers (order beeps, kitchen timer, ready-order polling). It is now rendered **outside the shell** (`App.tsx`, like the Owner app) with none of them. The KOT print host already refuses to run in a display window (`AutoKotPrinter`, `/customer-display` and `/kds-tv`).
- **The ported kitchen board had lost two things this app needs.** The offline board is not branch-scoped and polls every 10 s. Both were put back: orders go through `scopeToBranch` (including the "recently finished" strip, so another branch's cancellations never appear), and the 10 s poll stays behind the egress flag (off by default; realtime is the primary path).
- **A ported test that could not fail.** The offline "does not re-send an unchanged bill" test spies on the browser's storage prototype; the test environment here (happy-dom) keeps the method on the instance, so the spy saw nothing. The spy is now placed where the call goes.

## 3. NOT changed, and why
- **`/kds-tv` still runs inside the till shell** (as before): a kitchen TV beeping for new orders is wanted, and the KOT print host already stays out of it. Only `/customer-display` — a customer-facing screen — was taken out.
- **Two switches, as in the offline POS.** *Settings → Enable Display Screen* decides whether the till publishes the live bill; *Enable customer display* in the Center decides whether the Open button works. A shop that wants the bill on the customer's screen needs both. They are not merged here: merging would change a setting every offline-POS shop already knows.
- **The offline cross-window cache tests** (a second window re-reading one shared local database) were not ported: this app's windows load from Supabase and hear changes through realtime, so that failure cannot occur in the same way. Whether a second window stays current **has not been exercised against a live server** (see §4).
- **Voice wording.** The announcement list includes the offline POS's "Hindi voice" options (an Urdu sentence rewritten in Hindi script so a Hindi voice can read it, used only when no Urdu voice is installed). They are carried over unchanged.
- **Not built yet:** KOT designer, backup with images, the rest of the settings ecosystem (master directive #12).

## 5. NOT EXECUTED
- **A real second monitor** in the Windows app (choosing a screen, full-screen placement): covered by shell tests of the display list and placement maths, not run on hardware. The shell change is committed locally in `dtpos-desktop` and has not been built into an installer.
- **Spoken announcements** on a real PC: no speech voices exist in this environment; the logic and the "no voice installed" message are tested, the sound is not.
- **A live two-window run against Supabase:** an order moving to Ready in the till and the Customer Display updating by realtime. The browser check used one seeded local store.
- **Banners and video** from real files, on a TV.
- **The Windows installer** with the new IPC.
