# QAT and UAT — DT POS Enterprise v1.83.0 (online invoice verification)

Requested by the owner with the Super Admin redesign: "the invoice should be verifiable online".

## 1. What it is
Every Digital Target invoice (A4 and POS 80 mm) now carries a **QR code and an address**: `<site>/#/verify/<invoice id>`. The id is the invoice's own random uuid (122 bits: it cannot be guessed or counted up). The public page asks one database function, `public.verify_invoice(uuid)`, which answers with the invoice header and its payment state, or nothing for an unknown id. The Super Admin invoice preview has a **Verify link** button that copies the same address.

**What the function returns:** invoice number, issue and due date, total, paid total, status, the customer's restaurant name, and the issuer. It **never returns** line items, notes, e-mail or phone numbers.

**What the page proves:** the invoice exists in Digital Target's records for that customer and amount, and what its payment state is. It cannot prove a printed copy was not altered, so the page tells the reader to compare the number and total with the paper.

## 2. Database change (additive, applied to the project `drpzxzpvkpqfxcjbwypo`)
Migration `add_verify_invoice_function`: one `SECURITY DEFINER` function with a fixed `search_path`, `revoke all … from public`, `grant execute … to anon, authenticated`. No table, column or policy was changed.

| # | Check (run as the `anon` role in a rolled-back transaction) | Result |
|---|---|---|
| D1 | A real invoice id verifies for `anon` | true (status `unpaid`) |
| D2 | An unknown id returns null | true |
| D3 | `anon` still cannot read the table (`select count(*) from admin_invoices`) | 0 rows visible |
| D4 | The keys the function returns | total, due_at, issuer, number, status, customer, issued_at, paid_total — nothing else |

**Security note:** this is intentionally an anonymous-callable definer function; the Supabase advisor will list it with the others. It is acceptable because the input is an unguessable uuid and the output is minimal. It is not rate-limited; if abuse appears, add a Cloudflare rule on the verify path.

## 4. NOT EXECUTED
- Scanning a printed QR with a phone camera; a PDF/PNG export of the new invoice on a real device.
- The page in the packaged Windows/Android shells.
- Invoices created before this release carry the same uuid, so their QR works once they are re-opened and re-exported (they print no QR on paper already issued).
