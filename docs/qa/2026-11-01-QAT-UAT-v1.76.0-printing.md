## 2. Behaviour changes a reader must know (defects found and decisions taken)
| # | Finding | Decision |
|---|---|---|
| PD-1 | A bill saved straight to **Hold** printed nothing in the cloud POS. | **FIXED** — prints once on entering Hold (POS Hold button, edited bill, POS retrieve list, Running Bills). |
| PD-2 | The Kitchen button queued the KOT and then opened a window that printed it again (React state was stale in the handler). | **FIXED** — the window decides from the print queue, plus the order's own `kotPrinted` flag. |
| PD-3 | Margin range, text-weight model and slip-height measurement now follow v1.21.0 (−100…+100; three weight levels; content height + 4 mm, min 20 mm). Three cloud tests that pinned the older design were updated, each with the reason beside it. | **By request** ("same, 100%"). |
| PD-4 | Cloud-only safeguards (margins auto/manual, KOT stamped at enqueue, Firebase guards, screen-takeover CSS fix) were deliberately **kept**; they are not in v1.21.0. | Kept. |
| PD-5 | Token records are device-local (as in v1.21.0); not synced to Supabase. | Documented. |

## 3. NOT EXECUTED
- **Any real printer.** Fast printing, detection, margins and the alignment slip have only been exercised against the
  engine's own tests, not against a thermal printer. Until UAT-P1…P8 below pass on a real till, the printing claim is
  "tested in code", not "tested on a printer".
- The Windows installer `.exe` (`npm run dist`) and the Android shells.
- Cross-model printer behaviour (58 mm / 80 mm, USB / LAN / Bluetooth).
