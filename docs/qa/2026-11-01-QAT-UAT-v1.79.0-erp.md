## 2. Defects found while building, and decisions
| # | Finding | Decision |
|---|---|---|
| ER-1 | A negative result printed as "Rs.-200", which reads as a typing error on a profit line. | **FIXED** — printed "−Rs 200". |
| ER-2 | Receiving a purchase order must not double-count stock: stock and the moving-average cost are owned by `saveReceivingEntry`. | **DESIGNED** — the PO engine is a pure function that only *produces* receiving entries and never touches stock (a test pins that it does not mutate the order it is given); the page saves the entries through the existing `saveReceivingEntry`, which is the single place stock and the moving average change. |
| ER-3 | Supplier sends more than ordered. | **DESIGNED** — rejected unless the "supplier sent more" box is ticked; the extra is then recorded, not hidden. |
| ER-4 | Food cost cannot come from a stock count (there is no count module). | **DECLARED** — the statement is labelled *theoretical* (recipes × quantity sold). A stock-count module is a ranked gap (§4 item 5). |
| ER-5 | The cloud app has no double-entry ledger. | **OPEN** — ranked gap 3. The statements here are computed from the existing cash/party/payroll records and say so on the page. |
| ER-6 | Payroll is not per-branch; transactions and wastage filter by branch only if they carry a `branchId`. | **OPEN / DECLARED** on the page; a branch-filtered P&L therefore excludes payroll rather than guessing a split. |
