# QAT and UAT — DT POS Enterprise v1.91.0 (Owner app: Profit, Website switches, Devices, states, dark theme)

Design package build order, **step 4**, fourth part: the rest of the Owner app's screens that run on data the software already has (`design-project/06-owner-app`).

## 1. What was built
| Screen | What the owner sees and can do |
|---|---|
| **OWN-12 Profit and expenses** (More → Profit) | Revenue, cost of goods, expenses and profit for Today / Yesterday / Last 7 days / This month / This year, with bars and the biggest expense categories. An owner can pick one branch or all; a manager limited to some branches sees only theirs, one at a time.<br>It reads the same engine as the till's **Financial Statements**, so the two never disagree.<br>**It will not flatter:** if no sold item has a recipe, no profit is shown ("—") and the screen says why. If only some do, the figure is labelled "Profit, at most" with the share covered ("28% of item sales have a recipe"). |
| **OWN-20 Website and app switches** | Online ordering, Home delivery, Pickup and Guest checkout switches (the same settings as the Customer Portal page); delivery, pickup and guest are locked while online ordering is off.<br>Online orders **accepted at once** or **held for approval**.<br>Copy / Open / Share for the website, takeaway QR, delivery QR, table QR and tracking links.<br>**Opening hours** and **Banners and offers** are drawn as "Coming": the software has nowhere to store them yet. |
| **OWN-21 Devices** (More → Devices) | **Waiting for approval** on top with Approve and Remove; **approved** devices with online / last seen and Block; **blocked** devices with Unblock.<br>Block and Remove ask first. The phone the owner is holding can never block or remove itself.<br>A refusal by the database is said on the screen ("Not allowed: only the owner or an admin can change devices"), and a failed load shows a Retry banner. |
| **OWN-23 States** | Loading rows in the shape of the content; an **offline** banner on every screen ("showing the last data this phone loaded"); a Retry banner for a failed load; a screen the account may not open now says so, and who to ask ("Profit is not available to your account"), instead of quietly going to Overview. |
| **OWN-24 Dark theme** | Profile and workspace → Dark theme. Every Owner screen follows it, and it is kept on the phone. |

### Found in the browser check and fixed before release
- **Profit showed Expenses Rs 0 for an owner.** The screen decided "limited manager" before the account's branch access had loaded, picked the first branch, and so dropped every cost that carries no branch. It now follows the same rule as the rest of the app (unrestricted unless a restriction is known) and waits for the access to load. There is a regression test for it.
- Light-only colours (pink banners, pale badges) were hard-coded; they are now tokens, which is what lets the dark theme work. The light look is unchanged.
- "Website and app switches" was cut off by the Live badge; the status moved into its own row.

## 2. NOT changed, and why
- **Opening hours and banners** need new server storage; shown as "Coming", as the design marks them.
- **Notifications (OWN-18)** need a push service.
- **Owner sign-in screens (OWN-01/02/03)** are shared with the till's login; handled separately.

## Addendum (v1.95.0) — the website switches did not reach customers
The Website switches in this release (Online ordering, Home delivery, Pickup, Guest checkout) saved the setting correctly, but the customer website could not see it: an anonymous visitor cannot read the restaurant's settings, so the website ran on defaults and the database function that takes the order did not check the switches. The test in this release pinned the screen and the write, not the effect on a customer. Corrected in v1.95.0 (`docs/qa/2026-11-02-QAT-UAT-v1.95.0-website-switches.md`).
