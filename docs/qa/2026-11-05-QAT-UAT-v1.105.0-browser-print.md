# QAT / UAT — v1.105.0 · Browser printing prints the design

## The report
"The printout is not clean; what is designed changes in the browser. Please make the print templates exact."

## Cause (read in `src/printing/printCss.ts`)
The stylesheet is tuned for a 203-DPI thermal HEAD in the desktop app. `injectPrintCss` applied it to **every** print, including a browser's. It:
* repaints all text and borders black (greys and brand colours lost);
* forces 1 px black borders and `table-layout: fixed` on every table and cell;
* forces bold on headings and on the first column of every row (item names re-wrap);
* puts a grey + contrast filter on logos;
* fixes the content width;
* declares `@page { size: 80mm auto }` — not valid CSS (a page height cannot be `auto` beside a length), so browsers drop the whole size rule and fall back to their default paper.

## Fix
`buildBrowserPrintCss` — used by `injectPrintCss` when there is no desktop app: the template's own colours, borders, weights, fonts and width; `print-color-adjust: exact` on the slip so tinted bands and boxes print; `@page { margin: 0 }` and no invented size; the rest of the page hidden; Paper Save (compact) still honoured. The desktop app keeps `buildPrintCss` untouched. Settings → Printer: **Exactly as designed** (default) / **Print for a thermal head**.

## Update v1.105.1 — the root cause on the web
Rendering the real receipt templates in print media (not a sample) showed designed black bars with white text arriving as plain text, i.e. the template "inverted". The cause was not only the thermal stylesheet: `src/index.css` has `@media print { body * { color: #000 !important; background-color: transparent !important; … } }`, written for ledgers and reports, which erased every background and colour of the slip. It now excludes the slip when printing as designed (`html[data-print-design]`, set by `injectPrintCss`), so INVOICE / GRAND TOTAL / TOTAL FARE / RUNNING (UNPAID) / DELIVERY RECEIPT bars, shaded totals and boxes print as drawn. The invalid `size: 80mm auto` in that block is gone. The design stylesheet also keeps the desktop geometry (printable width, equal padding, calibration variables). The standard receipt's Rate / Amount columns (48 / 56 px) overlapped at 1,800.00; widened to 56 / 66 px.
Checked by rendering 25 receipt designs plus the KOT in print media in both styles: `docs/audit/2026-11-05-receipt-designs-printed-*.png`, `…receipt-print-thermal-vs-design-v1.105.1.png`, `…kot-printed-v1.105.1.png`. The KOT prints the same in both styles (it is black on white by design). The "pre-receipt" design did not render a slip in the harness under either style (it is not handled by this component); not investigated further.
