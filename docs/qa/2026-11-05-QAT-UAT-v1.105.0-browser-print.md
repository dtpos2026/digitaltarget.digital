# QAT / UAT — v1.105.0 · Browser printing prints the design

## The report
"The printout is not clean; what is designed changes in the browser. Please make the print templates exact."

## Cause (read in `src/printing/printCss.ts`)
The stylesheet is tuned for a 203-DPI thermal HEAD in the desktop app. `injectPrintCss` applied it to **every** print, including a browser's. It:
* repaints all text and borders black (greys and brand colours lost);
* forces 1 px black borders and `table-layout: fixed` on every table and cell;
* forces bold on headings and on the first column of every row (item names re-wrap);
* puts a grey + contrast filter on logos;
* fixes the content width;
* declares `@page { size: 80mm auto }` — not valid CSS (a page height cannot be `auto` beside a length), so browsers drop the whole size rule and fall back to their default paper.

## Fix
`buildBrowserPrintCss` — used by `injectPrintCss` when there is no desktop app: the template's own colours, borders, weights, fonts and width; `print-color-adjust: exact` on the slip so tinted bands and boxes print; `@page { margin: 0 }` and no invented size; the rest of the page hidden; Paper Save (compact) still honoured. The desktop app keeps `buildPrintCss` untouched. Settings → Printer: **Exactly as designed** (default) / **Print for a thermal head**.

* Paper size is still chosen in the browser's print dialog (browsers do not let a page pick a roll's height). Pick the roll / 80 mm paper there, with **Margins: None** and **Headers and footers: off**.
* The desktop app (Windows) printing is unchanged and was not re-tested here.
* Reports pages that print their own HTML in a new window were not changed.
