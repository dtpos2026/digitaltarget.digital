# QAT / UAT — v1.103.0 · Restore & sync, colour scheme switcher

## The report
"When I upload a backup, sync happens, the app sticks a lot. I do not know what the problem is. Please check."

## What the code does (read, not guessed) and what was wrong
| # | Finding | Effect |
|---|---|---|
| 1 | During a restore the app kept reacting to the cloud's change notices. Each notice reloaded a collection and treated every restored row the upload had not reached yet as "missing from the cloud" → **queued it again** | the same thousands of rows sat in the upload loop AND the retry queue |
| 2 | The retry queue's flush ran at the same time and uploaded those rows a second time | double load, "Pending N" that never cleared |
| 3 | A write-through op (bills, stock) made the queue rewrite its **whole contents** to disk, once per op | re-queueing N bills = N rewrites of an N-row queue (quadratic) — the freeze |
| 4 | One failed request marked the whole chunk of 100 rows as failed | rows quietly missing from the cloud |
| 5 | Pictures kept inside the data made single requests of many megabytes | time-outs |
| 6 | After a fixed 6 s the page reloaded; the progress event was fired but nothing listened | a big restore was cut off halfway, the screen showed nothing |

## Fix
Reloads and the queue's flush are held while a restore uploads and reconciled once at the end · one waiting queue write at most · chunk retries (0.8 s, 2.4 s) · requests bounded to 100 rows / ~1.2 MB · rows that still fail are queued and listed · restored records stamped as newest · a progress dialog that cannot be dismissed mid-upload and a summary of what is left · reload only when finished.

## Not executed — said plainly
* The owner's own backup and account were not available, so the hang was **not reproduced end to end against the real cloud**. The causes above are proven in code and by tests with a mocked cloud; whether they are the only cause on the owner's machine needs one real restore after this release. If it still sticks, the browser console lines starting `[import]` and the Sync panel's pending count say where.
* Realtime change notices for a restore still arrive (they cannot be switched off); they are now held and reconciled once.
* Windows shell rebuild (no shell change; it loads this web code).
