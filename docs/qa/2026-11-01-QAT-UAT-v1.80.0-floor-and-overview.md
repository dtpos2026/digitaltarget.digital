# QAT and UAT — DT POS Enterprise v1.80.0 (Advanced Floor View; Owner Overview dashboard)

Reference designs supplied by the owner: a floor-plan management screen (floors as tabs, colour-coded tables, status bar, actions panel) and a
restaurant-SaaS dashboard (KPI cards with trend lines, map, order-rate chart, gauge, recent orders). Only the **layout and presentation** were
adopted; colours, typography and data are DT's own.

## 2. Decisions and defects found while building
| # | Finding | Decision |
|---|---|---|
| AF-1 | There is no reservation module, so the reference's "Reserved" state and "Reservation Overview" button would have been placeholders. | **NOT ADDED.** A test pins that no Reservation button is offered. Reservations remain ranked gap 4. |
| AF-2 | "KOT not sent", "Food ready", "On hold" and "Over time" are derived from the live bill (kotPrinted, kitchenStatus, status, seatedAt); the limit for "Over time" is a per-device setting. | Documented in the UI (hover text) and in the Customize panel. |
| AF-3 | The status bar counts every table once (one state per table, most urgent first) so the chips always add up. | Pinned by a test. |
| AF-4 | The new view writes tables only through the existing `saveTable` / `deleteTable`; every bill action (move, merge, split, seat, pay) is handed back to the page's own dialogs. | One implementation of each; nothing can drift. |
| AF-5 | Take away / Delivery buttons needed a way into the order screen on a given type. | POS now reads `?type=takeaway|delivery`. |
| AF-6 | The dashboard has a new default for management (Overview); a cashier keeps the standard page. | A button on each page switches; the choice is remembered per device. |
| AF-7 | The reference shows no figures a restaurant could not verify; ours show only: sales, orders, average order, profit (each against the previous period), orders by week/month/year, sales by order type, delivery pins, recent bills, sync/print queue state. | No invented metrics (no "visitors age", no "menus" count). |

## 3. NOT EXECUTED
- A phone or tablet; Firefox/Safari; the Windows shell.
- Map tiles (the sandbox cannot reach OpenStreetMap; markers and the service-radius circle were seen on a grey base).
- The new Tables view with two devices at once (it reads the same tables/orders the other views do).
- Modern-style dashboard screenshot and a phone-width dashboard (the browser run stalled on the sandbox network; covered by the unit/page tests only).
